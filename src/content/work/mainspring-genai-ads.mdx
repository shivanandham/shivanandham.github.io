## Context

Mainspring is a creative agency that plans ad campaigns in Airtable: each campaign breaks into frames, each frame needs copy and a banner in several sizes. The platform's job was to generate those per frame, reliably, and push the results into the tools designers already use. I was the top backend contributor on the team, as a Francium Tech engineer.

## Constraints

- **The plan lives in Airtable** and keeps changing; the platform syncs from it rather than replacing it.
- **Generation is slow and flaky by nature.** Model calls time out and rate-limit; a banner that is half-generated must not look finished.
- **Copy has to come back in a fixed shape** (three options per frame, each with its parts), not as free text to be parsed.
- **The output goes to Figma, After Effects and Photoshop**, so there had to be a clean external API for assets.

## What I built

- **Retry-safe Celery generation tasks** with backoff and per-component status, so a failed call retries without duplicating work and the UI shows exactly which parts of a frame are done.
- **Structured-output prompting** with Google Gemini through Pydantic AI: three copy options per frame, validated into typed models before they are stored.
- **The outpaint geometry solver** that works out how a source image must be extended to reach each banner size before Stability AI outpaints it.
- **The external API** that delivers finished assets into Figma, After Effects and Photoshop.
- **Service-level tests** that helped raise backend coverage from 60% to 75%.

## The hard part

Making generation idempotent. A campaign has many frames and each frame has several components; model calls fail often enough that "retry the whole frame" would burn budget and produce duplicates. Each component carries its own status, each task is safe to re-run, and backoff is applied per call, so a retry picks up exactly where the previous attempt stopped. The banner side had its own geometry problem: extending an image to a new aspect ratio means deciding where the original sits and how much to outpaint on each side, which the solver computes before any pixels are generated. Service-level tests around these paths were what moved backend coverage from 60% to 75%.

## Outcome

- Copy and banners generated per frame from live Airtable plans and delivered into the designers' tools.
- Backend test coverage raised from 60% to 75%.
